Clean Architecture — 5 Layers
Layer 1 — Domain Core (zero dependencies)
Pure TypeScript. No React, no Axios, no Zustand. Framework-agnostic forever.
ReportDocument ReportSection ReportElement FormulaEngine RulesEngine LayoutEngine PrintTemplate (extended) DataBinding ThemeSystem
Layer 2 — Data Contract (ReceiptLiveData → UniversalDocumentData)
Single source of truth for all printable data. All previews consume this. No mock/demo data in components.
UniversalDocumentData DocumentDataBuilder ReceiptLiveData (alias) FieldRegistry CalculatedFieldService MOCK / MOCK_COMPANY
Layer 3 — Rendering Engine (renderer adapters)
Pluggable renderers. Core logic never touches DOM directly. Each renderer is swappable.
ReactRenderer ESCPOSRenderer PDFRenderer (future) printService.ts (adapted) RenderContext PaperSizeAdapter
Layer 4 — UI Components (React only)
Designer canvas, preview components, settings panels. Depend on Layers 1–3, never reverse.
DesignerCanvas ElementPalette PropertyPanel UniversalPreview PreviewSelector (simplified) TemplateManager ThemeEditor
Layer 5 — Integration (POS, Documents, Settings)
Thin wrappers. Existing pages call the framework. No print logic lives here.
POSPage (adapted) CommercialDocumentModal (upgraded) usePrintSettings (adapted) printStore.ts dual-save SettingsPage print block

Data Contract — UniversalDocumentData shape
interface UniversalDocumentData {
  // ─── Document identity ─────────────────────────────
  doc:      DocumentInfo;        // number, date, type, status, notes
  // ─── Parties ──────────────────────────────────────
  company:  CompanyInfo;         // name, address, nif, rc, nis, ice, logo
  party:    PartyInfo | null;    // customer or supplier
  // ─── Warehouse / Branch ───────────────────────────
  warehouse: WarehouseInfo | null;
  // ─── Session (POS) ────────────────────────────────
  session:   SessionInfo | null;
  // ─── Lines ────────────────────────────────────────
  lines:     DocumentLine[];     // full product + packaging + lot data
  // ─── Totals ───────────────────────────────────────
  totals:    DocumentTotals;     // ht, tva, ttc, stamp, discount, paid, change
  // ─── Tax breakdown ────────────────────────────────
  taxBreakdown: TaxRate[];       // per-rate: base, tva, total
  // ─── Payments ─────────────────────────────────────
  payments:  Payment[];
  // ─── Balances ─────────────────────────────────────
  balance:   BalanceInfo | null; // prev, current, new, due
  // ─── Currency ─────────────────────────────────────
  currency:  CurrencyInfo;
  // ─── Calculated (runtime) ─────────────────────────
  computed:  Record; // formula results, custom fields
}
Template Resolution Priority
1. User-selected template for (docTypeCode, paperSize)
2. Default template for (docTypeCode, any paperSize)
3. Default template for ('*', paperSize)          ← global fallback
4. createDefaultTemplate(docTypeCode, paperSize)   ← built-in hardcoded default

Storage: settings table only (key: print:templates:{docTypeCode}:{id})
Legacy: print_templates table → read-only migration path, no new writes
Architecture Decision Records
Storage backend
settings table only
Eliminate dual-save. print_templates table becomes read-only migration source. Single PATCH /settings endpoint.
Data contract
UniversalDocumentData
ReceiptLiveData becomes a type alias. All previews (thermal, A4, A5, future) consume the same object. No component-local MOCK data.
Rendering strategy
Renderer interface + adapters
IRenderer interface. ReactRenderer for screen/window.print(). ESCPOSRenderer for WebUSB. PDFRenderer as future plugin. Core has zero renderer knowledge.
Formula engine
Custom expression evaluator
No external dependency. Supports IF/SUM/CONCAT/FORMAT/TODAY + custom functions. Sandboxed, no eval(). Results cached per document.
Designer approach
Section-based (Phase 3+)
Phase 2: enhanced property panel (current UX). Phase 3: section drag/reorder. Phase 4: free-form canvas. Progressive — don't break existing UX.
Migration strategy
Additive + versioned templates
All existing PrintTemplate properties preserved. New framework adds optional fields. Template version field for future migrations. Zero breaking changes.
CommercialDocumentModal
Replace window.print()
Modal's print button calls UniversalPreview + ReactRenderer. Template resolved by document type. No window.print() in production paths.
Performance
Virtual table + memoization
Lines table virtualized (react-virtual). Formula results memoized per (template, data) pair. Preview debounced 200ms. No blocking renders.

Risk Analysis
Risk Impact Likelihood Mitigation
Dual-save bug: POS reads stale template after settings write fails High Current Phase 0: eliminate dual-save immediately. settings table is sole backend.
CommercialDocumentModal window.print() ignores template system entirely High Current Phase 2: wire to UniversalPreview. Until then, document as known limitation.
MOCK data in A4Preview / A5Preview renders in production if liveData is null Medium Possible Phase 0: remove MOCK fallbacks. UniversalPreview renders empty state explicitly.
FormulaEngine performance with 10k+ lines Medium Low Phase 1: memoize by (formula, args). Phase 4: virtual table. Lazy evaluation.
Existing print_templates DB rows become orphaned Low Certain (Phase 0) One-time migration script: read print_templates → write to settings table → mark migrated.
Designer Canvas coordinate math complexity Medium Medium Phase 3: use react-dnd or @dnd-kit. Don't write custom drag math. Snap grid simplifies placement.
RTL/Arabic rendering in PDF export High Likely Phase 3: use browser @page CSS print (Tajawal font already loaded). jsPDF has poor RTL support — avoid.
WebUSB thermal: ESC/POS Arabic Win-1256 encoding breaks with new data fields Medium Low ESCPOSRenderer wraps existing printService.ts. Encoding logic unchanged.
